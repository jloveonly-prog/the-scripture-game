# 🏜️ 테스트 계획서 작성 규격 (Template)

> **율법(Statute):** 이 문서는 테스트 계획서 작성 시 반드시 따라야 하는 **형식 규격**이다.

---

## 필수 섹션

| # | 섹션 | 필수 | 설명 |
|:--|:---|:---:|:---|
| 1 | 테스트 개요 | ✅ | 기간, 테스터, 환경 |
| 2 | 테스트 범위 | ✅ | 포함/제외 명시 |
| 3 | 자동화 테스트 — **Tier 1: DB 단위** | ✅ | DB CRUD 함수 검증, 인메모리 DB 격리 |
| 4 | 자동화 테스트 — **Tier 2: HTTP 통합** | ✅ | 라우트별 상태코드 + 응답 검증 |
| 5 | test 명령 실행 검증 | ✅ | `npm test`/`mvn test`/`pytest` 등 한 줄 명령으로 전체 통과 |
| 6 | 보안 테스트 | ✅ | 봉인의 율법 10계명 점검 |
| 7 | 성능 테스트 | ✅ | 응답시간, 동시접속, 메모리 |
| 8 | 버그 리포트 | ✅ | BUG-ID, 심각도, 상태 |
| 9 | 결과 요약 | ✅ | Pass Rate 수치 |

> 🚨 **Tier 1(DB)만 작성하고 Tier 2(HTTP)를 건너뛰면 Phase 5 불합격.**

## ID 규칙

| 대상 | 접두어 | 예시 |
|:---|:---|:---|
| 테스트 케이스 | TC- | TC-001 |
| 보안 테스트 | SEC- | SEC-001 |
| 성능 테스트 | PERF- | PERF-001 |
| 버그 | BUG- | BUG-001 |

## 정경화 조건

- Pass Rate 100% (Fail 0건)
- 보안 테스트(봉인의 율법) 전 항목 Pass
- 모든 BUG 상태가 Fixed

> **위반 시:** 광야의 불순물이 남아있다. 정경화 거부. 연단을 계속하라.
