# 📜 요구사항 추적 매트릭스(RTM) 작성 규격 (Template)

> **율법(Statute):** 이 문서는 요구사항 추적 매트릭스 작성 시 반드시 따라야 하는 **형식 규격**이다.
> 실제 산출물은 `bible-성경/01.requirement-hearing-들음/`에 작성하라.
> 작성 예시는 `parable-비유/01.requirement-hearing-들음/`을 참조하라.

> *"And the Lord said unto Moses, Write this for a memorial in a book."* — Exodus 17:14 (KJV)
>
> 모든 언약(Covenant)은 기록되어야 한다. 기록되지 않은 약속은 잊혀지고,
> 잊혀진 요구사항은 구현되지 않으며, 구현되지 않은 것은 구원(Deploy)에 이르지 못한다.
> RTM은 **요구사항과 산출물 사이의 언약(Covenant) 추적 장부**다.

아래 섹션이 하나라도 누락되면 정경화(Canonize) 불가:

| # | 섹션 | 필수 | 설명 |
|:--|:---|:---:|:---|
| 1 | 추적 매트릭스 본문 | ✅ | REQ ↔ 산출물 매핑 (아래 형식) |
| 2 | 커버리지 요약 | ✅ | 전체 REQ 대비 추적 완료율 |
| 3 | 미추적 항목 목록 | ✅ | 아직 산출물에 연결되지 않은 REQ |
| 4 | 설계 변경 이력 (Design Change Log) | ⚠️ (변경 발생 시 필수) | 정경화 이후 상류 설계가 개정될 때마다 기록 (아래 "재각 규칙" 참조) |

## 추적 매트릭스 형식

```markdown
| REQ-ID | 요구사항 요약 | UC-ID | ARCH-ID | API-ID | TBL-ID | 코드 모듈 | 테스트 ID | 상태 |
|:---|:---|:---|:---|:---|:---|:---|:---|:---:|
| REQ-001 | 회원가입 | UC-001 | ARCH-001 | API-001 | TBL-001 | UserService | TC-001 | ✅ |
| REQ-002 | 로그인 | UC-002 | ARCH-001 | API-002 | TBL-001 | AuthService | TC-002 | ✅ |
| REQ-003 | 주문생성 | UC-003 | — | — | — | — | — | ⬜ |
```

## 상태 범례

| 아이콘 | 상태 | 설명 |
|:---:|:---|:---|
| ⬜ | 미추적 | 아직 설계/구현에 연결되지 않음 |
| 🔄 | 부분 추적 | 일부 산출물에만 연결됨 |
| ✅ | 완전 추적 | 설계→구현→테스트 전 구간 연결 완료 |
| ❌ | 누락 확인 | 의도적으로 제외됨 (사유 기재 필수) |

## 커버리지 요약 형식

```markdown
| 지표 | 수치 |
|:---|:---:|
| 전체 REQ 수 | {N} |
| 완전 추적(✅) | {n₁} |
| 부분 추적(🔄) | {n₂} |
| 미추적(⬜) | {n₃} |
| 커버리지 | {n₁/N × 100}% |
```

## 성경적 검증 규칙

- **"기록하라"(Exodus 17:14):** 모든 요구사항은 반드시 이 장부에 기록되어야 한다. 기록되지 않은 REQ는 존재하지 않는 것과 같다.
- **"하나도 잃어버리지 않겠다"(John 6:39):** 단 하나의 REQ도 추적에서 빠져서는 안 된다. 미추적 REQ가 있으면 Phase 7(구원) 진입 불가.
- **양방향 추적:** 위→아래(REQ→코드)뿐 아니라, 아래→위(코드→REQ)로도 추적 가능해야 한다. Spec에 없는 코드가 존재하면 그것은 할루시네이션이다.

## 언약추적 갱신 규칙

| 시점 | 행동 |
|:---|:---|
| Phase 1 완료 시 | REQ 열 전체 등재. 나머지 열은 ⬜ |
| Phase 2 완료 시 | ARCH-ID, API-ID, TBL-ID 열 채움 |
| Phase 3 완료 시 | 화면 관련 항목 연결 확인 |
| Phase 4 완료 시 | 코드 모듈 열 채움 |
| Phase 5 완료 시 | 테스트 ID 열 채움 |
| Phase 6 완료 시 | 커버리지 100% 확인 |
| Phase 7 진입 전 | **모든 열 ✅ 필수. ⬜가 1개라도 있으면 구원 불가.** |
| (언제든) 상류 설계 결함 발견 시 | 위 순방향 갱신과 별개로, 아래 "설계 변경 이력 — 두 번째 돌판 규칙"에 따라 역방향으로 개정·재정경화한다 |

## 설계 변경 이력 — "두 번째 돌판" 규칙 (Design Change Log)

> *"And the LORD said unto Moses, Hew thee two tables of stone like unto the first: and I will write upon these tables the words that were in the first tables, which thou brakest."* — Exodus 34:1 (KJV)
>
> 첫 돌판(초기 설계)이 개발 중 깨어지는 것 — 즉 Phase 4~6에서 상류 설계의 결함이 발견되는 것 — 은 죄가 아니다.
> 방치하고 다시 새기지 않는 것이 문제다. 이 섹션은 그 "재각(再刻)"을 기록하는 곳이다.

### 재각 규칙 1 — 변경 이력 섹션 형식

```markdown
| 변경일 | 발견 Phase/지역 | 대상 ID(REQ/ARCH/API/TBL) | 변경 사유 | 영향받는 하류 산출물 | 재검증 필요 여부 | 상태 |
|:---|:---|:---|:---|:---|:---:|:---:|
| 2026-09-10 | Phase 4 / acts-행전 사마리아 배치 | API-003 | 결제 없는 프로젝트인데 응답 스키마에 가격 필드가 남아있어 수정 | api-gate-성문, OrderService 코드 | ✅ | 🔄 |
```

- `발견 Phase/지역` 칸에는 Phase 번호뿐 아니라 `acts-행전`을 쓰는 경우 지역명(예: "사마리아 배치")도 기재할 수 있다.
- `상태` 칸은 위 상태 범례(⬜/🔄/✅/❌)를 그대로 재사용한다 — 개정이 완료되어 재정경화될 때까지는 🔄로 둔다.

### 재각 규칙 2 — 역전파 (Backward Propagation)

Phase 4~6(또는 `acts-행전`의 어느 지역)에서 상류 설계 결함을 발견하면:

1. 해당 REQ 행을 매트릭스 본문에서 🔄(부분 추적)로 되돌린다.
2. 관련 상류 문서(`architecture-temple-성전설계`, `api-gate-성문`, `data-ark-법궤` 등)를 **개정(내용 보존 + 버전 +1)** 한다 — 기존 내용을 지우지 않고 새 버전으로 재각한다.
3. 개정된 문서를 재정경화한다.
4. 하류에 이미 연결된 코드/테스트 항목을 재검증 대상으로 표시한다.

### 재각 규칙 3 — 두 증인 확정

> *"In the mouth of two or three witnesses shall every word be established."* — Matthew 18:16 (KJV)

변경 이력 각 행은 CIE/SRD·Phase 6과 동일한 기준을 재사용한다: **발견 근거가 2곳 이상의 문맥(예: 코드 리뷰 + Witness 대조, 또는 테스트 실패 + RTM 원문 대조)에서 확인되어야 개정을 승인**한다. 한 곳에서만 의심되는 경우는 먼저 재확인부터 한다 — 성급한 재각은 또 다른 오류를 낳는다.

### 버전 표기 범위 (1차 결정)

> 2026-09-06 결정: **1차는 RTM(이 문서)에만 버전/변경이력을 적용한다.** `architecture-temple`/`api-gate`/`data-ark` 등 다른 정경화 문서 자체에 `v1, v2…` 헤더를 붙이는 확장은, 이 규칙을 실제 프로젝트에서 한 차례 사용해본 뒤 필요성이 확인되면 별도로 결정한다. 지금은 "그 문서가 개정되었다"는 사실 자체를 RTM 변경 이력에 남기는 것으로 충분하다 — 문서 본문에 버전 번호가 없어도, RTM 변경 이력의 변경일 순서가 곧 버전 이력 역할을 한다.

## 정경화 조건

- [ ] 모든 REQ가 매트릭스에 등재됨
- [ ] 미추적 항목에 대한 사유 기재 (의도적 제외만 허용)
- [ ] 커버리지 요약 작성 완료
- [ ] Phase 진행에 따라 열이 채워지고 있음
- [ ] 정경화 이후 상류 설계 변경이 있었다면, 설계 변경 이력 섹션에 반영되고 두 증인 확정을 통과했음

> **위반 시:** 언약을 기록하지 않는 자는 언약을 잃는다. 정경화 거부.
