# 가나안 분배 — 지파별 병렬 개발 오케스트레이션

`/canaan-orch`가 호출되면 이 세션은 **모세(오케스트레이터)** 역할을 맡는다. 이 스킬의 핵심은 코딩을 **실제로 여러 서브에이전트에 병렬 위임**하는 것이다 — 이 세션이 혼자 순차적으로 다 구현하는 것이 아니다.

## 0단계 — 발동 조건 확인 (강행 금지)

`.skill/scenario-시나리오/ORCH-01_canaan-가나안분배.md`의 "발동 조건" 3가지를 확인하라:
1. TIER-3 판별 여부 (`.skill/covenant-book-언약책.md` §1 기준)
2. `bible-성경/04.development-repentance-회개/task-wall-성벽.md`에 **서로 파일을 공유하지 않는 독립 도메인 3개 이상**
3. 도메인 간 "생성 파일" 경로가 겹치지 않음

조건 미달이면 즉시 사용자에게 알리고 `.skill/SKILL-04_repentance-회개개발.md`의 단일 순차 실행을 권장하라. 소규모인데 억지로 병렬화하면 통합 비용이 이득보다 크다.

## 1단계 — 영토 재구획 (이 세션이 직접, 코드 작성 없이)

`ORCH-01_canaan-가나안분배.md`의 "1단계" 형식대로 **지파 배정표**를 작성한다. 이때:
- task-wall-성벽의 TASK-ID를 파일 경로 기준으로 도메인 그룹핑
- 도메인 간 "생성 파일" 경로가 절대 겹치지 않는지 재확인 (겹치면 그 파일은 공통 선행 태스크로 승격)
- 지파 배정표를 사용자에게 보여주고, 되도록 진행 전에 확인받는다

## 2단계 — 공통 기반 선완료 (이 세션이 직접)

지파를 풀기 전에, 모든 지파가 의존하는 선행 태스크(DB 스키마, 공통 타입 등)를 **이 세션이 먼저 순차로 직접 구현**한다. 여기가 끝나기 전에는 서브에이전트를 절대 병렬로 띄우지 마라 — 전원이 같은 기반 파일을 놓고 충돌한다.

## 3단계 — 지파 발동 (진짜 멀티 에이전트 실행) ⭐ 핵심 단계

**Agent 도구로 지파 수만큼 서브에이전트를 한 메시지 안에서 병렬 호출**하라 (독립적인 호출은 반드시 한 응답에 동시에 실행 — 순차 호출 금지). 각 서브에이전트 프롬프트에는 반드시 아래를 포함하라:

- **자기 영토만** 명시: 담당 TASK-ID, 연결 REQ-ID, 생성/수정 대상 파일 경로 목록
- **경계 원칙**: "다른 지파의 파일 경로는 언급하지 않는다. 명시된 영토 밖의 파일은 절대 생성·수정하지 마라"
- `.skill/SKILL-04_repentance-회개개발.md`와 `statute-율법/04.development-repentance-회개/security-seal-봉인.md`(봉인의 율법 10계명) 준수 지시
- 완료 시 ORCH-01 문서의 "정복 완료 보고" 형식으로 보고하도록 지시

레위 지파(QA) 역할도 **별도 서브에이전트**로 같은 메시지에서 함께 병렬 실행하되, 특정 지파의 완료를 기다리지 않고 먼저 완료된 지파부터 순서 무관하게 감사하도록 지시하라 (완료 지파가 아직 없다면 대기 후 재확인하도록 지시).

> ⚠️ 이 세션(모세) 스스로 지파의 코드를 대신 작성하지 마라. 이 세션의 역할은 배정·발동·조정·통합이며, 실제 구현은 서브에이전트가 한다.

## 4~5단계 — 보고 수합 및 경계 분쟁 조정

모든 지파 서브에이전트의 "정복 완료 보고"를 수합하라. 파일 충돌이나 영토 침범이 발견되면 `ORCH-01_canaan-가나안분배.md`의 "5단계" 절차대로 이 세션이 직접 조정한다 — 경계표가 모호했던 경우에만 배정표를 수정하고, 명확한 침범은 해당 지파에게 되돌려 재작업시킨다.

## 6단계 — 통합 및 언약 계수

전 지파 완료 후:
1. 통합 빌드를 실행하라 (`task-wall-성벽`의 "3단계: 성문"부터 순서 재확인)
2. `/census-count` 스킬을 `bible-성경/01.requirement-hearing-들음 --phase 4 --log` 조건으로 실행하라
3. **IRONCLAD 확인 후에만** `bible-성경/04.development-repentance-회개/`에 정경화하고, 다음 단계(`SKILL-05_wilderness-광야.md`)로 안내하라
4. FAIL이면 누락된 REQ를 담당했어야 할 지파를 다시 소집(재병렬 실행)하여 보완하라

## 최종 심판

`ORCH-01_canaan-가나안분배.md`의 "이 시나리오 전용 심판 관문" 6개 항목(ORCH4-001~006)을 전부 확인한 후에만 사용자에게 통과를 보고하라.
