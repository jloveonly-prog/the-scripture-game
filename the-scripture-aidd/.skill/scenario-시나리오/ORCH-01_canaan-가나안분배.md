# ORCH-01: 가나안 분배 — 지파별 병렬 개발 시나리오

> *"And Joshua divided the land unto the tribes of Israel for an inheritance, according to their divisions."* — Joshua 11:23 (KJV)
>
> *"Thou shalt not remove thy neighbour's landmark, which they of old time have set in thine inheritance."* — Deuteronomy 19:14 (KJV)

## 📋 목적 (Purpose)

`SKILL-04_repentance-회개개발.md`는 단일 죄인(단일 에이전트/세션)이 순차적으로 성벽을 쌓는 것을 전제로 한다. 그러나 TIER-3(대규모) 프로젝트에서 `task-wall-성벽`에 독립 도메인이 여럿 존재하면, 단일 에이전트가 전부를 순차 처리하는 것은 여호수아가 가나안 전체를 혼자 정복하려는 것과 같다 — **가능하지만 느리고, 어텐션이 분산되어 위험하다.**

이 시나리오는 `bible-성경/04.development-repentance-회개/task-wall-성벽.md`에 확정된 태스크 분할표를 **도메인별 "영토"로 재구획**하여, 각 영토를 서로 다른 서브에이전트("지파")에게 **동시에** 정복(구현)하게 하는 병렬 오케스트레이션 절차다.

> ⚠️ 이것은 SKILL-04를 대체하지 않는다. task-wall-성벽 산출물과 SKILL-04의 모든 계율(SRP, 예외처리, 봉인의 율법)은 각 지파에게도 동일하게 적용된다. 이 문서는 **"누가, 어떤 경계 안에서, 어떻게 동시에" 일하는가**만 규정한다.

| 2 | `task-wall-성벽`의 태스크 의존성 맵에 **서로 파일을 공유하지 않는 독립 도메인이 3개 이상** 존재 | 의존성 맵(mermaid)에서 공통 선행 태스크(보통 TASK-001 DB 스키마) 이후 갈라지는 병렬 가지 수 확인 |

## 💬 실행 절차

### 1단계 — 영토 재구획 (모세)

`task-wall-성벽`의 태스크를 **파일 경계가 겹치지 않는 도메인** 단위로 묶어 "지파 배정표"를 만든다. 제비뽑기(Joshua 18:10, 무작위가 아니라 **공정하고 시비 없는 배정**을 상징)의 원칙에 따라, 배정 기준은 오직 **파일 소유권의 명확성**이어야 한다 — 선호나 난이도로 임의 배정하지 않는다.

```markdown
## 지파 배정표 (Tribal Allotment)
| 지파 | 담당 도메인 | 담당 TASK-ID | 영토(생성/수정 파일 경로) | 선행 완료 필요 |
|:---|:---|:---|:---|:---|
| 지파-1 (예: 유다) | UserService | TASK-002, TASK-004 | src/user/** | TASK-001 |
| 지파-2 (예: 단) | OrderService | TASK-003, TASK-005 | src/order/** | TASK-001 |
| 지파-3 (예: 아셀) | 프론트엔드 | TASK-006 | src/web/** | TASK-004, TASK-005 |
| 레위 (Levi) | — (영토 없음) | 전 지파 감사 | 읽기 전용 (전체) | — |
```

> ⚠️ **경계표 원칙 (Deuteronomy 19:14):** 한 파일이 두 지파의 "생성/수정 파일 경로"에 동시에 속하면 안 된다. 겹치는 파일이 있으면 그 파일을 담당할 단일 지파를 지정하거나, 해당 태스크를 공통 선행 단계(TASK-001류)로 승격하라.

### 2단계 — 공통 기반 선완료 (모세 → 단일 실행)

지파를 발동시키기 전에, **모든 지파가 의존하는 공통 선행 태스크(DB 스키마, 공통 타입 정의 등)를 먼저 단일 순차로 완료**한다 (Nehemiah 3의 기초 공사와 동일한 원칙: `task-wall-성벽`의 "1단계: 기반"). 이것이 끝나지 않으면 지파를 풀지 마라.

### 3단계 — 지파 발동 (병렬)

각 지파 서브에이전트에게 **자기 영토 행만** 전달하여 동시에 실행시킨다. 각 지파는 `SKILL-04_repentance-회개개발.md`의 모든 절차(SRP, 예외처리, 봉인의 율법 10계명)를 자기 영토 안에서 수행한다.

```
❌ 잘못된 발동: "지파-1, 전체 프로젝트를 봐줘"
✅ 올바른 발동: "지파-1, 너의 영토는 src/user/**다.
   담당 TASK: TASK-002, TASK-004
   연결 REQ: REQ-001, REQ-002 (task-wall 참조)
   다른 지파의 영토(src/order/**, src/web/**)는 절대 건드리지 마라.
   완료 시 '정복 완료' 보고 형식으로 여호수아에게 보고하라."
```

### 4단계 — 정복 완료 보고 (지파 → 여호수아)

각 지파는 영토를 완료하면 아래 형식으로 보고한다.

```markdown
## 정복 완료 보고 (Conquest Report) — 지파-1
| 항목 | 내용 |
|:---|:---|
| 담당 TASK-ID | TASK-002, TASK-004 |
| 완료 파일 | src/user/UserService.ts, src/user/userController.ts |
| 연결 REQ | REQ-001, REQ-002 |
| 봉인의 율법 10계명 점검 | ✅ 위반 0건 |
| 예외처리 적용 | ✅ 전 라우트 적용 |
| 영토 침범 여부 | ✅ 없음 (src/user/** 외 파일 미수정) |
```

### 5단계 — 경계 분쟁 조정 (여호수아)

두 지파가 같은 파일을 수정했거나, 한 지파가 타 지파 영토를 침범한 경우:

1. 여호수아가 먼저 지파 배정표(경계표)를 재확인한다
2. 경계표가 명확한데 침범했다면 → 침범한 지파에게 되돌리게 하고 재작업 지시
3. 경계표 자체가 모호했다면 → 여호수아가 임시 조정 후, **모세에게 경계표 수정을 보고**한다 (여호수아 임의로 경계표를 영구 변경하지 않는다)

### 6단계 — 레위 지파 상시 감사 (병렬 진행)

레위 지파는 특정 지파의 완료를 기다리지 않고, **완료 보고가 올라오는 즉시** 해당 영토를 감사한다 (전 지파 동시 진행 가능). 감사 항목은 `SKILL-05_wilderness-광야.md`의 사전 점검 항목(코드 복잡도, API 일관성, 설계-코드 불일치)을 선제 적용한다.

### 7단계 — 통합 및 언약 계수 (여호수아 → 모세)

전 지파의 "정복 완료" 보고가 모이면:

1. 여호수아가 **통합 빌드**를 실행한다 (`task-wall-성벽`의 "3단계: 성문"부터 순서 재확인)
2. `UTIL-census-언약계수.md`의 계수기를 **`--phase 4`**로 실행하여, 모든 REQ의 "코드 모듈" 열이 지파별로 빠짐없이 채워졌는지 확인한다
   ```bash
   python .skill/tools-도구/census-count-언약계수.py bible-성경/01.requirement-hearing-들음 --phase 4 --log
   ```
3. `IRONCLAD`가 아니면 → 누락된 REQ를 담당했어야 할 지파를 재소집하여 보완
4. `IRONCLAD` 확인 후 → 모세가 `bible-성경/04.development-repentance-회개/`에 최종 정경화, `SKILL-05_wilderness-광야.md`(광야/테스트)로 진행
